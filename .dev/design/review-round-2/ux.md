## A. 구체화 스펙 (확정 수치)

### 1. 토글 애니메이션 타이밍 + 햅틱

미완 → 완료(체크 채움)와 완료 → 미완(되돌림)은 **속도를 비대칭**으로 둔다. 완료는 "성취감 있게" 살짝 느리게, 되돌림은 "취소니까" 빠르게.

| 요소 | 미완→완료 | 완료→미완 | 곡선 |
|------|-----------|-----------|------|
| 체크박스 fill (배경 알파 0→100%) | 180ms | 120ms | `FastOutSlowInEasing` |
| ✓ 마크 등장 (scale 0.6→1.0 + alpha) | 160ms, fill보다 40ms 지연 시작 | 즉시 사라짐(80ms) | `OvershootEasing`(살짝 튕김) 미완→완료만 |
| 텍스트 취소선 그리기 (좌→우 clip) | 200ms | 100ms | `LinearEasing` |
| 텍스트 색 → muted | 180ms crossfade | 120ms | — |
| row 정렬 이동(완료 sink, D9) | 250ms, 토글 애니 끝난 뒤 시작 | 동일 | `FastOutSlowInEasing` + `animateItemPlacement()` |

- 총 체감 = 약 200~250ms. 250ms 초과하면 "느리다", 100ms 미만이면 "안 눌렸나" → 이 범위 사수.
- **햅틱**: 미완→완료 = `HapticFeedbackConstants.CONFIRM`(또는 Compose `HapticFeedbackType.LongPress`에 대응하는 confirm). 완료→미완 = `CLOCK_TICK`급 가벼운 tick 또는 햅틱 없음(되돌림은 시각만으로 충분, 과한 진동은 오터치 오인 유발).
- **소리 기본 OFF**(R1 확정 유지). 시스템 햅틱 OFF면 시각 애니만.
- row 정렬 이동은 토글 애니와 **동시 진행 금지** — 누른 항목이 손가락 밑에서 곧장 움직이면 "내가 누른 게 이거 맞나" 혼란. fill+✓가 끝나고(약 200ms) 나서 sink.

### 2. Undo 스낵바 — 지속시간 / 위치 / 동작 (메인 전용)

R1 D4에서 "메인 ✕ + Undo 스낵바" 확정. 구체화:

- **지속시간 = 5초**(`SnackbarDuration` 커스텀 5000ms). 4초는 노안/주의분산 사용자에게 짧고, 7초+는 다음 액션을 가린다. 5초가 표준 절충.
- **위치 = 화면 하단**, 입력창(추가 input)이 하단에 있으면 **입력창 위로 띄운다**(`Scaffold`의 `snackbarHost`가 IME/입력 영역 위에 뜨도록 bottom padding 적용). 입력창을 가리면 "추가하려는데 스낵바가 막는" 충돌.
- **카피**: `"'{할일}' 삭제됨"` + 액션 `"실행취소"`. 할 일 텍스트가 길면 말줄임(앞 12자 + …). 예: `"'팀 회의 자료 준비하…' 삭제됨 [실행취소]"`.
- **연속 삭제**: 여러 개를 빠르게 지우면 스낵바를 **큐잉하지 말고 최신 1개만**. 단 실행취소는 "직전 1건"만 복구(다건 복구는 스코프 밖, 휴지통 아님). 이 한계를 스낵바 카피로 드러내지 말되 동작은 직전 1건 고정.
- **실행취소 시 복구 위치**: 삭제 전 인덱스로 되돌린다(맨 아래로 가지 않게). 인덱스 유실 시 맨 위.
- 스낵바 떠 있는 동안 **삭제는 아직 영구커밋 보류가 아니라 즉시 커밋 + 복구는 재삽입**으로 구현(SharedPreferences 단순 저장 모델 유지). soft-delete 테이블 안 만든다 — 스코프 절제.

### 3. 빈 상태 카피 (잠금화면 / 메인, 상황 분기)

R1 #12에서 "완료로 비운 경우 vs 원래 없는 경우 구분" 지적. 확정 카피:

| 화면 | 상황 | 카피 | 비고 |
|------|------|------|------|
| 잠금화면 | 할 일이 원래 0개 | `오늘 할 일이 없어요` | 중립. 이모지 없음(잠금화면 미니멀) |
| 잠금화면 | 있었는데 전부 완료 | `오늘 할 일 다 끝냈어요` | 작은 체크 아이콘 1개(accent), 축하 텍스트만. 폭죽 이모지 ❌(공공장소·과함) |
| 메인 | 0개 | `+ 아래에 첫 할 일을 추가해보세요` | 입력창으로 시선 유도, 입력창 강조(테두리 accent) |
| 메인 | 전부 완료 | `오늘 할 일 다 끝냈어요` (+ 완료 목록은 그대로 노출) | 메인은 완료도 보여줘야 되돌림 가능 |

- "전부 완료" 판정 = 항목 수 > 0 AND 미완 = 0. 잠금화면에서만 이 분기로 메시지 전환.
- 카피는 **존댓말·짧게**. 느낌표/이모지 남발 금지(R1 톤). 한 줄, 16~17sp, muted가 아니라 **본문 대비 충족 색**(빈 상태 텍스트가 안 보이면 의미 없음).

### 4. 긴 텍스트 말줄임 규칙

R1 #11에서 규칙 부재 지적. 확정:

- **잠금화면**: 최대 **2줄**, 초과 시 `TextOverflow.Ellipsis`(…). row 최소높이는 1줄 기준 56dp, 2줄이면 자연 확장하되 상한 둔다(아래 C-새결함과 연동).
- **메인**: 최대 **2줄** 표시 + 말줄임. 전체 내용은 항목 탭 시 인라인 펼침 또는 (스코프 절제) 그냥 2줄 말줄임 고정. 1차는 **2줄 말줄임 고정**(편집 화면 없음).
- **입력 길이 소프트 제한**: 60자. 60자 도달 시 입력 막지 말고(하드 컷 ❌) 카운터 `52/60`를 입력창 우하단에 회색으로, 60 초과 시 카운터만 빨강 + 추가 버튼 비활성. 잠금화면 가독성·레이아웃 안정성을 입력 단계에서 보호.
- **줄바꿈 단위**: 한글은 글자 단위 줄바꿈(`LineBreak.Heading`/기본 word break 한글 자동) — URL/영문 긴 토큰은 강제 분절(`break-word`)로 카드 밖 삐져나옴 방지.
- ✓ 박스·삭제 ✕는 텍스트 줄 수와 무관하게 **상단 정렬**(`Alignment.Top`) — 2줄일 때 박스가 가운데 떠서 첫 줄과 어긋나 보이는 것 방지.

### 5. 권한 온보딩 체크리스트 — 단계 설계 (메인)

R1 #16에서 "상태형 체크리스트" 방향 확정. 구체 단계/카피/상태:

순서 의존 3단계. 각 단계는 `완료 ✓ / 지금 필요 ● / 잠김 ○`(앞 단계 미완 시 잠김) 3상태.

| # | 단계 | 미완 상태 카피 | 액션 버튼 | 완료 표시 |
|---|------|----------------|-----------|-----------|
| 1 | 다른 앱 위에 표시(오버레이) 권한 | `잠금화면 위에 표시하려면 권한이 필요해요` | `권한 설정` → 시스템 설정 딥링크 | ✓ `표시 권한 허용됨` |
| 2 | 알림 권한 (Android 13+) | `서비스 실행 알림에 필요해요` | `허용` → 런타임 권한 요청 | ✓ `알림 허용됨` (12 이하면 단계 자체 숨김) |
| 3 | 잠금화면 서비스 켜기 | `이제 켜면 잠금화면에 할 일이 떠요` | `서비스 켜기`(토글) | ✓ `작동 중` (초록 점) |

- **전부 완료 시**: 체크리스트는 **한 줄 배너로 접힘** — `잠금화면 할 일 작동 중 ✓`(탭하면 다시 펼침). 목록이 주인공(spec §3-2).
- **순서 가드**: 2·3단계는 이전 단계 미완이면 비활성(`○ 잠김`) + 회색. "왜 못 누르지" 방지 위해 잠긴 단계에 `1단계를 먼저 완료해주세요` 보조 텍스트.
- **영구 거부 감지**: 런타임 권한이 "다시 묻지 않음"이면 버튼 카피를 `설정에서 직접 허용` + 설정 딥링크로 전환(dead-end 방지, R1 #16).
- **미리보기 버튼**(R1 #18): 체크리스트 **밖, 완료 배너 옆 보조 텍스트 링크**로만(`미리보기`). 1급 버튼 강등 확정.
- 권한 거부 상태에서도 **목록·추가·테마 선택은 동작**해야 한다(권한은 잠금화면 표시에만 필요, 앱 자체 기능은 막지 말 것). 거부 = 빈 화면 dead-end 금지.

## B. decisions.md 미해결 (UX 관련) 답

### 6. 자체 시계 vs OS 시계 중복 — "전체 대체"가 맞다 (패널 오버레이 ❌)

decisions.md 미해결: "OS 잠금화면 위 패널이 아니라 전체 대체가 맞나."

**결론: 우리 화면이 OS 잠금화면을 전체 덮는 현재 방식이 옳다. 단 "OS 잠금화면을 흉내 내되 더 낫게"가 원칙.**

근거(사용자 관점):
- 반투명 패널로 OS 잠금화면 위에 얹으면 **시계가 2개**(OS 시계 + 우리 시계)가 동시에 보여 명백한 혼란 + 정렬 충돌. 이건 사용성 사고다.
- 전체를 우리 배경(테마 그라데이션)으로 덮으면 OS 시계가 안 보이므로 **우리 시계 1개만 남아 중복 해소**. R1 #5에서 지적한 "blur가 무의미"와도 일관 — 우리가 배경을 칠하니 blur 뺀 반투명 단색 카드(D2)가 정합.
- 대신 **OS 시계와 시각·포맷이 어긋나면 안 된다**(D7). 위치도 OS 관습대로 상단 중앙(현 목업 맞음). "낯선 화면"이 아니라 "익숙한 잠금화면 + 할 일"로 느껴져야 신뢰.

이탈/혼란 방지 조건(스펙에 명시):
- 우리 화면에서도 **시각 동기 오차 0**(1분 tick OS 따름). 손목 OS 시계와 1분이라도 다르면 "이거 가짜 시계?" 신뢰 붕괴.
- 우리 화면은 **잠금 상태를 바꾸지 않는다**(체크만, 잠금해제 아님). 사용자가 "스와이프 = 잠금해제"라는 OS 멘탈모델을 유지하도록, 위로 스와이프/홈 제스처는 우리가 가로채지 말고 OS로 패스(아래 C 새결함과 연동).
- spec §3-1에 **"앱이 불투명 테마 배경을 전체 렌더, OS wallpaper 투과 안 함"** 한 줄 확정 기재(R1 #5 (a)안 채택).

### 7. 가로 모드 — 1차는 세로 고정 (가로 미지원 명시)

**결론: 잠금화면·메인 모두 세로(portrait) 고정. 가로 회전 미지원.**

근거:
- 잠금화면 글랜서블은 **거의 100% 세로 한 손** 사용. 가로 잠금화면 자체가 OS에서도 드문 케이스.
- 가로 대응 = 시계 64sp·카드·체크리스트 레이아웃 재설계 비용이 큰데 사용 빈도가 극히 낮다 → YAGNI.
- 구현: `android:screenOrientation="portrait"` (LockActivity, MainActivity). 태블릿도 1차 세로 고정.
- **단 회전 시 크래시/깨짐은 금지** — 고정이므로 회전 이벤트 자체가 안 와야 한다(고정으로 원천 차단). spec §비목표에 "가로 모드 미지원" 명시.

### 8. 폰트 확대(접근성) — 1.3배까지 보장, 상한 클램프

decisions.md 미해결 + R1 #10 연동.

**결론: 시스템 글꼴 확대를 따르되, 잠금화면은 레이아웃 붕괴 방지를 위해 폰트 스케일 상한을 1.3배로 클램프.**

- 본문 할 일 텍스트 기본 **17sp**(R1 #10 권장, 16→17 상향 확정). sp 단위 유지(사용자 확대 반영).
- 시스템 폰트 스케일 1.0~1.3배: 그대로 따름. **1.3배 초과**: 잠금화면 카드/시계가 화면을 넘기므로 잠금화면 한정 `fontScale`을 1.3으로 클램프(`LocalDensity` override). 메인은 클램프 없이 시스템 전체 따름(스크롤 가능하니).
- 시계(64sp)는 **고정 dp 환산하지 말고** 스케일 따르되, 1.3배에서 2줄 안 되게 시:분 단일 baseline 유지(자릿수 4 + 콜론 기준 폭 확보).
- 큰 글꼴 + 2줄 말줄임(A-4) 조합 검증: 1.3배 × 2줄 = row 높이 상한 약 96dp, 이 이상은 1줄 말줄임으로 강등(잠금화면 한정).
- **최소 글꼴(0.85배)** 도 깨지지 않게 — row 최소높이 56dp는 dp 고정이라 작은 글꼴에서도 터치영역 유지(R1 D6과 정합).

### 9. 라이트 테마(B) 야간 눈부심 — 시스템 다크 연동 안 함 (수동 유지)

decisions.md 미해결.

**결론: 테마는 수동 선택 유지(spec §비목표). 시스템 다크모드 자동 전환 ❌. 단 야간 눈부심은 별도로 완화.**

- spec 비목표가 "다크모드 자동 전환 없음"이므로 B를 야간에 자동으로 A로 바꾸지 않는다 — 사용자가 고른 테마가 멋대로 바뀌면 그게 더 큰 혼란.
- 다만 잠금화면은 **밤에 가장 자주 켜지는 화면**(자기 전 확인)이라 순백(#f4f5f7) 풀스크린은 눈부심이 크다. 완화책:
  - B 잠금화면 배경을 순백 대신 **아주 옅은 회색 그라데이션**(#f4f5f7 → #e9ebef)으로 미세 톤다운(대비는 D3 유지).
  - 또는 1차는 손대지 말고 **"야간엔 A 추천" 한 줄 안내**를 테마 선택 옆에 표기(자동 전환 대신 사용자 선택 유도). → 1차 채택: **안내만**. 배경 톤다운은 P2.

## C. R1이 놓친 새 사용성 결함

### 10. [P1] 우리 잠금화면이 OS 잠금해제 제스처를 삼킬 수 있다

R1은 "우리 화면이 OS를 덮는다"는 컨셉만 짚었고, **덮은 상태에서 사용자가 정작 잠금해제를 어떻게 하는지**를 안 다뤘다.

- 우리 Activity가 풀스크린 위에 떠서 모든 터치를 먹으면, 사용자가 "위로 스와이프해서 잠금해제"하던 동작이 안 먹혀 **갇힌 느낌** → 최악의 첫인상.
- **개선:** 카드 영역 밖(상단 시계/하단 여백)에서의 스와이프·홈제스처는 우리가 가로채지 말고 OS로 패스. 체크 탭만 우리가 소비하고 나머지는 통과. "할 일 카드만 인터랙티브, 나머지는 평소 잠금화면처럼 동작"을 명시.
- 검증 항목 추가: 우리 화면 떠 있을 때 **정상 잠금해제(PIN/지문/스와이프)가 막힘 없이 되는지** 에뮬 실측.

### 11. [P1] 자정 경과 시 "오늘 할 일"의 의미가 깨진다 (날짜 없는 모델의 함정)

R1 #14는 "완료 잔존"만 봤다. 더 근본 문제: **카드 라벨이 "오늘 할 일"인데 데이터에 날짜가 없다**(spec 비목표). 어제 만든 미완·완료 항목이 자정 넘어도 "오늘 할 일"로 그대로 보인다 → 라벨이 거짓말.

- 사용자: 어제 "장보기"를 깜빡 완료처리 안 했는데 오늘 잠금화면에 "오늘 할 일: 장보기 ✓(어제 완료)"가 섞여 신뢰 하락.
- 날짜 필드 추가는 스코프 밖(비목표). **카피로 해결:** 카드 라벨을 `"오늘 할 일"` → **`"할 일"`** 로 변경(D9는 "라벨 통일"만 합의, 문구는 미확정이므로 R2에서 `할 일`로 확정). "오늘"이라는 시간 약속을 코드가 못 지키니 라벨에서 뺀다.
- 빈 상태 카피(A-3)도 `오늘 할 일이 없어요` → 유지 가능(빈 상태는 "지금" 시점 사실이라 거짓 아님). 단 채워진 카드의 헤더 라벨만 `할 일`.
- 일일 리셋/날짜 필드는 spec §8에 **"향후 과제"로 명시 보류**(R1 #14 재확인).

### 12. [P2] 첫 항목 삭제 시 입력창만 남아 "삭제됐나" 불확실 + 스낵바와 빈상태 충돌

메인에서 마지막 1개를 ✕로 지우면 → 목록이 빈 상태(A-3 카피)로 즉시 전환 + 동시에 Undo 스낵바(A-2)가 뜬다. 둘이 같은 하단 영역에서 겹쳐 **"+ 첫 할 일을 추가" 안내를 스낵바가 가린다.**

- **개선:** 빈 상태 전환은 스낵바 dismiss(5초) 후 또는 crossfade로. 스낵바 떠 있는 동안엔 빈 상태 일러스트/CTA를 살짝 위로 밀거나 페이드인 지연. 둘이 같은 순간 같은 자리 점유 금지.
- 마지막 항목 삭제는 빈도 높은 엣지(다 끝내고 정리) — 이때 화면이 깔끔히 전환돼야 "완주" 만족감.

### 13. [P2] 테마 세그먼트가 항목 위 공간을 상시 점유 — 한 번 고르면 거의 안 바꾼다

R1은 "테마 즉시 프리뷰"(D10)는 칭찬했지만, **세그먼트가 메인 상단을 영구 차지**하는 비용을 안 봤다. 테마는 설정 후 거의 안 바꾸는 저빈도 액션인데 고빈도 액션(추가/체크)보다 위에 있다 → 시각 위계 역전(spec이 고치려던 문제 3의 변형).

- **개선:** 1차는 세그먼트 유지하되 **상단 헤더 안에 작게**(타이틀 옆 A/B/C 작은 칩 3개). 목록 위 큰 블록으로 만들지 말 것. 첫 실행 후 접근 빈도가 낮으면 P2에서 설정 이동(D10도 "항목 늘면 설정으로" 단서 있음 — 테마는 안 늘지만 사용 빈도 근거로 동일 결론).
- 검증: 메인 첫 화면에서 **할 일 입력창과 목록이 fold 위(스크롤 없이)** 보이는지. 세그먼트가 이걸 밀어내면 실패.

### 14. [P2] "작동 중"인데 화면이 안 떴을 때 사용자가 알 방법이 없다 (silent failure)

체크리스트 3단계 완료 → 배너 "작동 중 ✓". 하지만 OS가 백그라운드 서비스를 죽이거나(제조사 배터리 최적화), 오버레이 권한이 나중에 회수되면 **배너는 여전히 "작동 중"인데 잠금화면엔 안 뜬다.** 사용자는 앱이 고장났는지 자기가 뭘 잘못했는지 모른다.

- **개선:** 메인 진입(onResume) 시마다 권한·서비스 실제 상태를 재확인해 배너 갱신. "작동 중" 표기를 prefs 저장값이 아니라 **실시간 권한/서비스 체크 결과**로 렌더. 회수 감지 시 체크리스트 자동 재펼침 + 해당 단계 ●로.
- 제조사 배터리 최적화 화이트리스트 안내(`자동 시작/배터리 제한 해제`)는 1차는 **도움말 텍스트 링크**로만(전기종 딥링크는 스코프 밖).
