## A. 글래스 fill 확정값 (D2 구체화)

R1 D2로 blur는 폐기·반투명 solid fill + 1px border로 확정됐다. 폐기했으므로 "blur 폴백 쌍"이 아니라 **단일 fill 값**을 박는다. 카드는 그라데이션 위를 덮으므로, 카드가 화면 어느 높이에 와도 동일하게 읽히도록 fill alpha는 카드 아래 배경의 최저 명도 기준으로 정한다.

**1. 테마 A 카드 fill — `rgba(255,255,255,0.10)` 유지하되 border를 `0.16`으로 상향.**
- fill `#FFFFFF @ 0.10`, border `#FFFFFF @ 0.16` (현재 .14). blur가 없으니 카드 경계는 오직 border가 만든다. .14는 #1a1438 같은 더 어두운 하단 그라데이션 위에서 1px가 거의 사라진다. .16으로 올려 경계를 살린다.
- 본문 흰 텍스트(#FFF)는 합성 카드(#3a315a 근방) 위에서 **11.9:1**로 여유. fill alpha는 텍스트 가독성이 아니라 "패널이 떠 보이는가"만 결정하므로 .10이면 충분.

**2. 테마 C 카드 fill — `rgba(255,255,255,0.70)` 유지, border `#FFFFFF @ 0.55` **추가**(현재 없음).**
- C는 밝은 크림 배경 위 흰 70% 카드라 blur 없으면 카드/배경 경계가 거의 안 보인다(둘 다 밝음). 1px white .55 border + 아주 옅은 shadow `0 6 18 rgba(180,110,80,.12)`로 카드를 띄운다.
- 텍스트 #5b3a2e는 합성 카드(흰 70% over 크림 ≈ #fff6ef) 위에서 약 **8.5:1**, 안전.

**3. 카드 fill을 "단색 합성값"으로도 함께 박아라(투명 합성 비용 제거).**
- Compose에서 매 프레임 alpha 합성하지 말고, 디자인 토큰에 **불투명 등가값**을 같이 적는다: A `#332B4F`(배경 #241a48 위 white .10 합성), C `#FFF6EF`. 구현자가 그라데이션 위 어디든 이 단색을 쓰면 결과가 일정하다. (배경 그라데이션 구간마다 합성 결과가 달라지는 걸 막는 게 핵심 — §G-15 새 결함과 연결.)

## C. 완료 항목: 취소선 + 불투명도 수치 (D3 구체화)

R1 D3로 "색 죽이기 대신 취소선+불투명도"를 정했다. **전 테마 공통 opacity = 0.60**으로 통일한다(테마별 muted 색을 따로 만들지 않음 → 토큰 단순화).

**4. 완료 텍스트 = 베이스 텍스트색 그대로 + `alpha 0.60` + 취소선.**
- 계산: A `#FFF@0.6` over 카드 = **5.43:1**, B `#23262E@0.6` over #fff = **4.13:1**, C `#5B3A2E@0.6` over 카드 = 약 **5.0:1**. 셋 다 본문 가독 하한(완료=de-emphasis라 4:1대 허용) 안에 들어온다.
- 이렇게 하면 `design-tokens.md`의 완료 전용 muted색(A #8a85a8, B #b6bac3, C #c9a392)은 **삭제**. 완료색 = 베이스색 × 0.6 한 규칙으로 수렴.

**5. 취소선 스펙 명시.** 두께 `1.5dp`, 색 = **완료 텍스트와 동일 합성색**(별도 색 금지). 위치 text-decoration 중앙. 취소선이 너무 옅으면 "완료" 신호가 약해지므로 텍스트와 같은 alpha를 공유해 일관 유지.

**6. 완료 정렬 = 하단 sink (D9 구체화).** 미완료(생성순) → 완료(완료시각 desc). 잠금화면·메인 동일. 완료 묶음 위에 `1.5dp` 여백 또는 옅은 구분(B만 divider) 1줄. 완료 5개 초과 시 "n개 완료" 접기는 R3 검토(지금은 전부 표시).

## D. 8dp 그리드 + 타입스케일 확정값 (R1 §B·C 구체화)

| 토큰 | 값 | 용처 |

## E. 체크박스 벡터 스펙 (R1 #14·#15 구체화)

**10. ✓ = vector path(폰트 글리프 폐기).** 24dp 박스 기준(C는 26dp):
- viewport 24×24, ✓ path `M6 12.5 L10.5 17 L18 7.5`, **stroke 2dp**(C는 2.5dp), strokeCap·strokeJoin = round, fill none.
- 박스 radius: A 8dp / B 원형(50%) / C 9dp (목업 유지). border 미완 2dp, 색은 토큰의 미완 외곽선.
- 색: A/B `#FFFFFF`, C `#5B3A2E`(on-accent).

**11. 토글 모션 확정.** 채움 box `scale 0.9→1.0` 150ms `FastOutSlowIn`, ✓ path `trimPathEnd 0→1` draw-in 180ms, 텍스트 취소선·alpha는 120ms fade. 해제는 역재생 동일. row만 갱신(D5). duration/easing 토큰화하되 200ms 넘기지 말 것(잠금화면 손맛은 즉답성이 생명).

## F. decisions.md 미해결 — 디자인 답

**13. 3테마 분기 비용(devil) — 답: 분기 0, 토큰 교체만.**
- `AppTheme` data class 1개(필드 약 30개: 색 18 + radius 4 + weight 4 + shape/elev 4) × 인스턴스 3개 + `LocalAppTheme` CompositionLocal 1개. **Composable 본문에 `when(theme)` 금지** — 모든 컴포넌트는 `LocalAppTheme.current.xxx`만 읽는다. 분기는 인스턴스 정의 3곳에만 존재.
- 추정 비용: 토큰 정의 ~120줄(3×40) + 컴포넌트는 테마 무지(theme-agnostic). 테마 추가 시 인스턴스 1개(~40줄)만 늘어남. YAGNI 우려는 "구조 분기"가 아니라 "값 테이블"이라 유지보수 선형 증가에 그친다 → 3테마 유지 타당.

**14. 라이트(B) 야간 눈부심 — 답: 자동 다크 전환 안 함(비목표·수동 선택 충돌). 대신 잠금화면 B 배경을 한 단계 낮춘다.**
- 자동 시스템 다크모드 연동은 "테마는 수동 선택"(SPEC §2 비목표)과 정면 충돌 → **채택 안 함**.
- 대안: **잠금화면 전용 B 배경 = `#ECEEF1`**(메인 #f4f5f7보다 한 톤 낮춤) + 카드 흰색 유지. 메인은 밝게, 잠금(야간 빈번)만 살짝 눌러 눈부심 완화. 기기 자체 Night Light/밝기 자동에 최종 위임. (테마 정체성은 유지, 명도만 −4%.)

**15. 잠금화면 "전체 대체 vs OS 위 패널"(devil #2) — 답: 전체 대체(full-bleed)가 맞다.**
- 이 앱은 잠금화면 경험 자체를 제공하므로 위젯 오버레이가 아니라 **풀블리드 배경 + 떠 있는 카드**가 정답. 단 우리가 OS 잠금을 덮는 순간 OS 시계가 가려지므로 **우리 시계는 필수**(자체-OS 시계 중복 우려 해소). 디자인적으로는 "패널이 떠 있다" 인상을 카드 border/elevation로만 만들고 배경은 전체를 채운다.

## G. R1이 놓친 새 결함

**16. 상태바/노치(컷아웃) 세이프에어리어 토큰이 없다.** 목업 시계 top 70px는 고정값이라 펀치홀·다이내믹아일랜드·큰 노치 기기에서 시계와 겹친다. → 시계 top = `WindowInsets.statusBars` + `space.xl`(24)로 동적 계산. 세이프에어리어를 토큰이 아니라 인셋에서 받도록 스펙에 명시. (잠금화면은 기기를 안 가린다.)

**17. 할 일이 많을 때 카드 오버플로/스크롤 어포던스 미정.** 잠금화면 카드가 화면 높이를 넘으면? → 카드 `maxHeight = 화면 − 시계 − 세이프에어리어`, 내부 스크롤 + 하단 8dp **fade-out 그라데이션**으로 "더 있음" 암시. 메인은 일반 스크롤. R3 전에 max 표시 개수 정책도 필요.

**18. 테마 전환 모션 미정(D10은 "즉시 프리뷰"만).** 다크(A)↔라이트(B) 하드 스왑은 잔상/번쩍임으로 거슬린다. → 배경·카드·텍스트 색을 **220ms crossfade**(`animateColorAsState`)로 전이. 세그먼트 선택 → 아래 목록 색이 부드럽게 바뀌는 게 개인화의 손맛.

**19. 세그먼트 컨트롤 자체 시각 스펙이 없다(R1 #18은 위치만 결정).** → height 36dp, radius `chip` 토큰, 트랙 배경 `disabled-fill`, 선택 칸 fill = 카드색 + accent 1.5dp border + 라벨 accent색, 미선택 라벨 muted. A/B/C 라벨은 텍스트("다크/라이트/따뜻") 또는 색 스와치 점. 폭은 3등분 균등.

**20. muted 토큰이 이름 없는 2값으로 모호하다.** `design-tokens.md`가 A muted를 `#8a85a8 / #b8b2d8` 두 값으로 슬래시 표기 → 어느 게 날짜고 어느 게 완료인지 불명. C도 `#c9a392 / #b07d63`. → **`muted-strong`(날짜/라벨)·`muted-weak`(보조)** 두 토큰으로 분리 명명. 완료색은 §C-4로 베이스×0.6이 됐으니 기존 "완료 전용 muted"는 제거되고 muted는 날짜·empty·secondary 용도로만 남는다.

**21. 빈 상태 레이아웃 불균형.** 할 일 0개면 카드가 라벨+문구만 남아 납작해지고 큰 시계 밑에 작은 카드가 떠 어색하다. → 빈 상태는 카드 `minHeight 96dp`, 문구 수직 중앙 정렬, `empty-text` 색 + 위에 옅은 체크 아이콘(accent @0.4, 28dp) 1개. "오늘 할 일이 없어요" 한 줄.

## 핵심 개선점 5 (R2 수렴안)

1. **글래스 fill 확정**: A fill #FFF@.10 / border #FFF@.16, C fill #FFF@.70 / border #FFF@.55 + 옅은 shadow. 불투명 등가값(A #332B4F, C #FFF6EF) 병기로 그라데이션 위 합성 일관성 확보(§A, §G-16 연결).
2. **상태 토큰 실값 표 확정** + on-accent.C = #5B3A2E(4.33:1)로 코랄 ✓ 대비 통과, destructive는 평상 muted/확인 빨강(§B).
